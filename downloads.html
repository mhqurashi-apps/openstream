Not in this build

  • Windows Flutter client .msi — needs MSVC + the Flutter windows desktop toolchain; .github/workflows/ci.yml package-windows
  • macOS .dmg — needs macOS + Xcode; .github/workflows/ci.yml package-macos
  • iOS .ipa (unsigned) — needs Xcode; .github/workflows/ci.yml package-ios
  • macOS server — no x86_64-apple-darwin target and no macOS SDK on this host; macOS binaries are CI-only

What this build does, and does not

Proven on a real Android 14 device against a real Linux host in phase 31:

  • the host captures its X11 display, encodes H.264, and publishes it to the session; the device decodes and shows the picture;
  • a swipe on the phone is injected into the host's X server and moves its pointer;
  • pairing by deep link and by pasted link, runtime enrollment without a server restart, both control channels, and the signed ClientHello.

Still missing or unproven in this build:

  • the host must run an X11 session; there is no Wayland, macOS or Windows capture backend;
  • the Windows client .msi, macOS .dmg and iOS .ipa are not built (they need native toolchains);
  • keyboard injection is not driven on a device, and frame rate, cursor latency and bitrate adaptation are not measured end to end;
  • nothing is code-signed; Android warns on sideload and SmartScreen warns on the MSI.

The evidence, the exit codes and every limit are documented in infra/e2e-flutter-device.md and docs/TESTING.md. The device proof used a diagnostics build of the same client so the app could report its decoded-frame counter; the shipping APK is that client with the diagnostics constant compiled out.

Verify a file you downloaded

Put the file in a directory with MANIFEST.txt, open a terminal there, and run:

sed -n 's/^\([0-9a-f]\{64\}\)  [0-9]*  /\1  /p' MANIFEST.txt | sha256sum -c -

Every line ends in OK when the files are intact. One FAILED line means that file is corrupt or not the one this build produced — do not install it. Without the manifest, compare a single file against the table above:

sha256sum OpenStream-0.1.1-server-amd64.deb

Install, in plain language

Two halves, clearly labelled: OpenStream Server is the computer you reach, OpenStream Client is the screen you look at. Every server file below installs and starts with no other package needed — FFmpeg travels inside it.

OpenStream Server — Linux (.deb)

sudo apt install ./OpenStream-0.1.1-server-amd64.deb

Needs nothing else. The only declared dependency is libc6; the FFmpeg libraries are in /usr/lib/openstream-server/lib. Start it deliberately with sudo systemctl start openstream-server — the package installs the unit but does not enable it. The unit prints the pairing QR in the journal and makes the session server listen on 0.0.0.0:40076, so a phone on your network can reach it; the metrics page stays on 127.0.0.1:40075. An openstream-server you start by hand keeps the safe loopback default on both ports.

OpenStream Server — AppImage

chmod +x OpenStream-0.1.1-server-x86_64.AppImage && ./OpenStream-0.1.1-server-x86_64.AppImage --help

Needs nothing installed and no FUSE: on a machine without FUSE, prefix the command with APPIMAGE_EXTRACT_AND_RUN=1. Run it with no arguments and the session server listens on 0.0.0.0:40076 (metrics stays on 127.0.0.1:40075); pass --signaling-addr yourself to listen somewhere else.

OpenStream Server — Flatpak

flatpak install --user ./OpenStream-0.1.1-server-x86_64.flatpak
flatpak run dev.openstream.OpenStreamServer --help

No OpenStream package and no FFmpeg needed. Flatpak fetches the shared freedesktop runtime the bundle is built against; that is the only download. The bundle's launcher passes --signaling-addr 0.0.0.0:40076 for you (metrics stays on 127.0.0.1:40075); a --signaling-addr you add to flatpak run wins.

OpenStream Server — tarball (no package manager)

tar -xJf OpenStream-0.1.1-server-linux-x86_64.tar.xz
./openstream-server/openstream-server --help

Needs nothing installed. Keep the lib/ directory next to the binary.

OpenStream Client — Linux (.deb)

sudo apt install ./OpenStream-0.1.1-client-amd64.deb

This is the one artifact that still needs apt to install two desktop libraries — libgtk-3-0t64 and libsecret-1-0 — and apt install ./file.deb fetches them for you. Start it as OpenStream Client from the application menu, or run openstream-client.

OpenStream Client — AppImage and Flatpak

chmod +x OpenStream-0.1.1-client-x86_64.AppImage && ./OpenStream-0.1.1-client-x86_64.AppImage
flatpak install --user ./OpenStream-0.1.1-client-x86_64.flatpak

Needs nothing else: the AppImage carries GTK 3, and the Flatpak bundle gets GTK from the freedesktop runtime Flatpak installs for you. Both need a graphical desktop session.

Android client (.apk)

Copy the APK to the phone and tap it, or adb install OpenStream-0.1.1-android.apk. Android will ask you to allow installing from an unknown source: the build is debug-signed, not Play-signed. Nothing else to install.

OpenStream Server — Windows (.msi)

Double-click it. SmartScreen warns because the installer is unsigned. The installer brings its own FFmpeg DLLs. The Windows client is not in this build: it needs the MSVC toolchain and is produced by CI only.
