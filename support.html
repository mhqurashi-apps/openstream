Support

OpenStream · last updated 15 November 2026

The short version. OpenStream is community-run. There is no support desk and no paid tier — you talk to the people who write the code, and a fix you send upstream becomes part of the project.

Something is broken

Open an issue on the project tracker and include:

  • the host operating system and version, and the client platform;
  • the OpenStream version or commit you are running;
  • what you expected, and what happened instead;
  • the relevant part of the log, with device names removed.

Screen captures of the pairing screen and of the streaming view are often the fastest way to explain a problem.

Connection problems

  • Both devices on the same network, no connection. Check that the host is advertising over mDNS and that the client can see _openstream._udp.local.. Some enterprise and guest Wi-Fi networks block mDNS; a wired path or a self-hosted mesh works there.
  • Works locally, fails over the internet. The host and the client need a path: STUN/TURN, a Headscale or NetBird mesh, or a relay you operate yourself. Check that the relay is reachable.
  • Works, but the picture is soft. The client sharpens the stream when it is below the display's native resolution; the sharpness control in the session menu trades sharpness against latency.

Build it yourself

The repository is public and every dependency is open source.

git clone https://github.com/MHQurashi/openstream.git
cd openstream
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings

Cross-platform installers (Windows .msi, macOS .dmg, Linux .flatpak and .deb, Android .apk, unsigned iOS .ipa) are produced by open-source CI on every push. iOS builds are unsigned, so they need to be signed on your own machine with an Apple developer certificate before they will install.

Ask a question

Use the discussions area of the project tracker for "how do I" questions. Questions that turn out to be common are usually answered by a page here, so the next person finds it without asking.
